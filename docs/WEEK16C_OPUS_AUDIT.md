# W16c 독립 점검 (Opus 5.5, 2026-10-25)

1.6.0 병합(2780739) 직후, 앞선 세션의 결론을 다시 확인했다. 재현 스크립트는 `spikes/w16c/audit_*.py`에 있다.

## 1. 정답 v3의 기하 편향 → 결과가 부풀려지지 않음
- 정답 v3는 탐지기와 같은 끝점 기준선 기하를 요레이트에 적용해 만든다. 센서는 독립이지만 정의가 같아서 재현율이 부풀려질 수 있다.
- 그래서 기하와 무관한 정답을 따로 만들었다. 이름은 **깜빡이 의도 사건**이다(`audit_blinker_truth.py`).
  - 깜빡이 켜짐 1~15초, 평균 40km/h 이상, 앞뒤 최저 30km/h 이상
  - 앞뒤 구간의 방향 변화 20° 미만(회전·램프 제외), 구간 경계 4초 제외
  - 결과: 1.6.0이 **10/11**, 1.5.2가 **4/11**을 잡았다.
  - 표본이 11건이라 방향 확인용으로만 쓴다. 기하 편향 때문에 개선폭이 부풀려졌다는 증거는 없다.

## 2. 1.5.2 수치 정정 (기획서·README 반영)
- 앞선 세션은 1.5.2를 정답 v3로 재지 않은 채 "약 6%"로 적었다. 실측은 다음과 같다.
  - 현대 **4/32(13%)**, 기아 **0/28**
- "1.5.2는 틀린 카드 0장"이라는 말도 정답 v2 채점 방식의 산물이었다. 자이로로 확인하면 결과가 다르다.
  - 1.5.2가 낸 차선 카드: **7장 중 3장 확인(43%)**
  - 1.6.0: **51장 중 31장(61%)**
- 따라서 1.6.0은 "재현을 얻고 정확도를 잃은" 버전이 아니다. 두 지표 모두 같거나 낫다. 다만 1.5.2 쪽 표본이 7장이라 정확도 비교는 대략적이다.

## 3. 기아 홀드아웃 오염 정도
- 조향비 20은 7차종 추정값의 중앙값이다.
- 현대 4차종만으로 정하면 19.05가 된다(엘란트라 13.9·소나타 18.6·싼타페 19.5·팰리세이드 27.4). 이미 잰 조향비 19의 기아 결과는 17/28(61%)이다.
- 즉 현대만 보고 정했어도 기아는 57~61%다. 오염이 결론을 바꾸지 않는다. 70% 기준은 여전히 미달이다.

## 4. 미확인 탐지를 핸들 특징으로 줄일 수 있나 → 없음
- 현대 32건(확인 16·미확인 16)으로 분포를 비교했다(`audit_unconfirmed.py`).
- 비교한 특징: 옆 이동, 방향 최대, 속도, 모양 점수, 창 길이, 속도 변화율, 원시 핸들 진폭.
- 사분위가 모두 겹친다. 모양 점수만 조금 다르다(중앙값 0.55 대 0.41).
- 32건으로 문턱을 더 고르면 과적합이 된다. 시도하지 않는다. 자이로가 없는 Connect SDK에서는 이것이 구조적 한계다.

## 5. 실차 위험 점검
| 항목 | 확인 | 판단 |
|---|---|---|
| 입력 순서 뒤바뀜 | 250ms 넘게 늦은 입력은 창 전체를 비움. 앱은 같은 신호의 과거 시각 입력을 미리 거름 | 보수적. 실차 콜백 지연이 250ms를 넘으면 사건을 놓칠 뿐 틀린 카드는 안 냄 |
| 속도 갱신 | 기록 서비스가 `PERF_VEHICLE_SPEED`를 SENSOR_RATE_UI로 구독. AVD에서는 일정 속도에서도 주기 갱신 | 실차 VHAL이 ON_CHANGE처럼 동작하면 정속 3초 뒤 창이 재시작돼 놓칠 수 있음. **실차 미확인** |
| 깜빡이 초기값 | 구독 직후 `getCurrentTurnSignalState`로 초기값을 읽음 | 깜빡이 정보 부족(SIGNAL_GAP)으로 모든 카드가 숨는 상황은 막혀 있음 |
| 급제동과 차선 카드 동시 발생 | 시뮬에서는 15~23%였으나 실데이터 급제동 3장 중 0장 | 실데이터 근거 없음. 급제동 표본이 적어 결론은 보류 |
| 보이는 '확인 필요' 카드 | 74분에 39장(1.5.2는 66장). 25km/h 미만 경로·급제동 미확인 후보이며 상당수가 1분 조각의 시작·끝 | W16c가 만든 문제 아님. 실제 전체 주행에서는 줄어들 것으로 보이나 미측정 |
