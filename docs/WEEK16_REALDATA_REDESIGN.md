# W16 — 실주행 지연 창 재설계 후보 / 1.6.0(21)

2026-10-25. **회귀를 지키지 못해 명세의 멈춤 조건으로 중단했다. 이 후보는 사용/제출 가능한 1.6.0이 아니다.** 판정 값을 더 고르지 않았고 **기아 추론·채점은0회**다. 현대 수치를 개선하려고 기아를 보거나 정답/채점 기준을 바꾸지 않았다. 실패 상태의 코드와 근거를 보존한다.

## 실행 순서와 결정

1. [W16 진단](WEEK16_REALDATA_DIAGNOSIS.md)을 전체 읽고 제공된 `ccs_window_v2.py.detect`·원본 `ccs_eval_v2.py`를 확인했다. 기존 Git에 수정된 `logic/build/` 산출물이 있어 보존하고 새 산출물은 `build/w16/`로 격리했다.
2. 기준 Python 함수를 AVD/Example fixture에만 실행한 사전 확인: run1은12.6~39.8초, run2는12.4~39.6초 한 구간으로 합쳐지고 Example_1에도8.3~19.3초 후보가 나왔다. 이때 기아는 실행하지 않았다.
3. 10Hz·고정 링버퍼·중심 이동평균·3~8초 창·겹침 합치기 후보를 구현하고 **현대54구간만** 실행했다. 초기 경고 기준2.5m/1.5°는 정답 밖 미사용 경고13.89건/시간으로 실패했다.
4. 현대 요약만으로 경고 문턱16조합(옆 이동2.5/3.0/3.5/4.0m × 방향 최대1.5/2.0/2.5/3.0°)을 단조 필터로 비교했다. 경고 상한 두 개를 지킨 조합 중 clean을 가장 많이 남긴 **4.0m/1.5°**를 선택하고 실제 엔진으로 재실행했다. 후보 순위 함수는 문턱과 별개로 고정해, 사후 필터와 실제 재실행의19/35·정답 밖2건 결과가 일치했다.
5. `build/w16/frozen.json`의 로직/fixture/정답/평가 원본29파일 해시를 고정하고 필수 회귀·Gradle을 확인했다. **AVD3종과Example_1이 모두 실패**하여 구현/값 선택을 중단했다. 기아 holdout은 소모하지 않았다. 이후에는 고정 후보의 시뮬·마지막 소스 시험·보고만 실행했다.

## 고정 후보 구현과 비용

`DelayedLaneWindow.kt`가 순수 로직이다. 원시 핸들각과 AAOS m/s를100ms grid로 표집하고 `yaw≈v·θ(rad)/(15·2.7)`를 계산한다. SDK ON_CHANGE 무변화는 마지막 값을 유지하고, 같은 grid 시각의 나중 콜백은 마지막 점을 교체한다. **Python의 선형 보간과 달리 ZOH 표집**이며 이 차이는 남은 한계다.

| 항목 | 후보 값/구조 |
|---|---|
| 링버퍼 | Motion160점(약16초), Signal 전이 최대256개/최근20초+경계 상태, 병합 구간 요약1개 |
| 도로 성분 | 앞30점~뒤29점, 60점 중심 평균. 미래30점이 찰 때 고역 성분 결정 |
| 탐색 | 길이30~80점,5점 간격(3~8초,0.5초 간격), 시작2점 이동(0.2초) |
| 기하/속도 | 방향 최대≥1.2°, 끝 방향≤max(1.5°,최대40%), 옆2~6m, 평균≥30·최저≥25km/h |
| 워밍업 | 첫 유효 동작 표본(+0.5초) 뒤4초. 명시 미수신·5초 초과 공백 뒤 재시작 |
| 표시 문턱 | 미사용 경고는 추가로 옆≥4.0m·방향 최대≥1.5°. 현대만으로 선택 |
| 깜빡이 | 원 시각의 방향별 전이 이력, lookback3초. `WEAK_LANE_EVIDENCE`는 내비 보조가 제거하지 못하는 근거 부족 플래그 |
| 확정 | 시작 순서로 모든 길이를 검사한 뒤 겹치는 창 합치기. 다음 가능한 시작이 병합 끝을 넘으면 확정. P/Finish는 남은 창 처리 |

| 저장 | 원시 링은 메모리만. 요약v6에 `windowDurationMs` 숫자1개 추가. 위치/VIN/원시 시계열 저장·전송 없음 |

표본당 상한은 코드 주석에 적었다: 일반10Hz 표본에서 고정 길이160점 목록 복사/검색, 도로 평균60회 덧셈, 두 표본마다 최대80회 적분(sin80회·문턱11회). 신호 콜백도256개 이내의 전이 이력만 다룬다. 공백 따라잡기는 기존5초 제한으로 최대50표본이며, 종료 경계 재계산/남은 창 검사는160점 범위 안에서만 돈다. 실행 시간에 비례하는 이력이나 검색은 없다. **CPU/RAM 실기 측정은 하지 않았다.**

최대 길이8초와 미래 평균3초가 모두 필요해 창 시작 처리 지연은 최대약11초다. 합친 후보 사슬이 길면 확정도 더 늦어진다. 영점이 바뀌어도 중립을 기다리는 자기 잠금은 피하지만, **병합 사슬의 사건 경계 문제는 해결되지 않았다.**

## 경계·근거·재현

기존 `.local/` 서명 키·설정은 열거나 변경하지 않았다. 기존 Gradle은 Debug에서도 release 설정을 읽으므로 `-PisolatedVerification=true`에서 해당 읽기를 건너뛰게 했다. 검증용 임시 키는 새 `build/w16/debug.keystore`, JVM home/temp·Android home은 `build/w16/`, 기존 키와 분리한다. 출력 buildDirectory도 `build/w16/gradle/`로 바꿨다. Release에는 이 옵션을 허용하지 않는다. `.local/`의 실제 서명 설정/키는 건드리지 않았다.

```powershell
# 현대만: 기아 CSV를 읽지 않는 접두사 필터
$env:RECAP_REAL_DIR='C:\data\commaCarSegments\csv'
$env:RECAP_REAL_PREFIX='HYUNDAI_'
$env:RECAP_REAL_OUT="$PWD\build\w16\hyundai-final.jsonl"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/test-logic-offline.ps1 -OutputRoot build/w16/runtime -TestClass lab.pleos.observe.logic.recap.RealDataBatchTest
C:\data\tools\capvenv\Scripts\python.exe -B scripts/realdata/score-hyundai.py build/w16/hyundai-final.jsonl
Remove-Item Env:RECAP_REAL_DIR,Env:RECAP_REAL_PREFIX,Env:RECAP_REAL_OUT

# 기존 서명 키/설정 없이 전체 Gradle 검증: 현재 실패하는 후보
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/verify-w16.ps1
# 마지막 전체 JVM(현재 실패)
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/test-logic-offline.ps1 -OutputRoot build/w16/runtime
```

기아/전체 batch 명령과 원본 `ccs_eval_v2.py engine <jsonl>`은 **이번에는 실행하지 않았다**. 따라서 `real_v160.jsonl` 전체 데이터 결과나 기아 속도대 표의 숫자는 없다. 기아70%를 통과/실패했다고 추정하지 않는다. 회귀를 고친 새 설계를 고정한 뒤 한 번의 holdout 평가로 남겨 둔다.

중요 SHA-256:

```text
truth_v2.json  EC7E0CFE90B8C3A6425A516F3D2C4B299540924B6C61AC35E72A53BFB199A754
ccs_eval_v2.py 15EBE52B03C8BC0A2F0E4E2CA9C43CDAE3ABFA6A8C10AD4040D2D5C6EF12C6CA
```

동결29파일 해시는 평가 후 그대로다. 모든 새 파일/수정은 이 저장소 안에서만 수행했고, 외부 정답/CSV/도구는 읽기만 했다. `build/w16/`의 원시 측정 산출물은 기존 ignore 범위로 보존한다. 보고용 증거는 `docs/evidence/realdata/w16/`에도 보존하며 기존 ignore 범위다. 비밀 키는 증거/패치에 포함하지 않는다.

**로컬 커밋은 미수행:** 이 세션의 파일 권한 정책에서 `.git`이 읽기 전용이다. 사용자 승인은 있지만 그 경계를 넘어서 쓰거나 다른 저장소에 우회 커밋하지 않았다. 소스/문서만 포함한 `build/w16/w16-candidate.patch`로 검토 가능한 변경을 남긴다. 기존 수정 build 산출물을 stage하지 않았고 push도 하지 않았다.

재개 전에는 **중복 창의 사건 경계**, **곡선 진입·이탈 거절**, **깜빡이 미수신/약한 후보의 표시 정책**을 먼저 다시 정해야 한다. 이 세 문제를 고친 뒤에도 현대만으로 정책을 고정하고, 필수 CSV를 통과한 다음 기아를 평가해야 한다. 이번 후보를 수치상 합격으로 만들기 위한 추가 조정은 하지 않았다.
