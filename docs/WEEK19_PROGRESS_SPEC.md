# 1.9.0 설계: 지난 7일과 비교 · 잘한 순간 모으기 (2026-10-26)

## 왜
- 사용자 결정(2026-10-26): "지난주와 비교 · 잘한 순간 모으기"를 넣는다. 목적은 **계속 쓰게 만드는 장치**. 점수·랭킹·남과의 비교는 넣지 않는다("점수 대신, 내가 몰랐던 순간" 정체성).
- 톤: 운동 앱 기록처럼 담백하게. 칭찬 과잉·게임 효과음·폭죽 없음. 숫자와 짧은 문장.

## 개인정보·보존 원칙 (지금 정책 유지)
- 지금 정책: 원본 요약은 2일, 종류별 개수(`WeeklyCountStore`, `recap-counts-v1`)는 7일만 남는다. **이 보존 기간은 늘리지 않는다.**
- 그래서 비교 기준은 "지난주(달력 주)"가 아니라 **"지난 7일 평균"**이다(이미 있는 7일 개수로 계산 가능). 화면 문구도 "지난 7일 평균"으로 정확히 쓴다.
- "잘한 순간 모으기"는 날짜·위치·시각 없이 **누적 숫자 몇 개만** 따로 저장한다(아래). 기록 삭제 버튼을 누르면 함께 지운다.

## A. 지난 7일과 비교
- 하루 집계(`CountDay`)에 **켬 거리 합계와 개수**를 더한다(평균 계산용, 같은 날 먼저 켠 차선 변경·회전 카드의 `signalLeadMeters`). `CountCodec` 버전을 올리고 옛 기록은 켬 거리 없음으로 읽는다(테스트로 보장).
- 비교 항목(오늘 vs 지난 7일 중 주행한 날의 평균):
  1. 놓친 순간 수(깜빡이 없이 차선 변경·회전 + 늦게 켬, 켜 둔 채 주행은 따로 세는 기존 분리 유지)
  2. 깜빡이 켬 거리 평균(m)
  3. 잘한 순간 수
- 비교할 지난 날이 없으면 그 줄은 "지난 7일 기록이 쌓이면 비교해 드려요" 한 줄만.
- 문장 예: "놓친 순간 1번 · 지난 7일 평균 2.4번", "켬 거리 평균 40m · 지난 7일 평균 28m보다 12m 일찍". 좋아진 쪽만 파랑 강조, 나빠진 쪽은 강조 없이 숫자만(혼내는 느낌 금지).
- 위치: 복기 화면 오른쪽 열 "오늘 한눈에" 바로 아래 새 카드 "지난 7일과 비교". 좁은 화면이면 기존 규칙대로 아래로.

## B. 잘한 순간 모으기
- 새 저장소(앱 파일, 원자적 쓰기, 기존 `WeeklyCountStore`와 같은 방식): 누적 값 3개만.
  - `goodTotal`: 지금까지 모은 잘한 순간 수(카드가 확정될 때 1씩, 같은 카드 id 중복 집계 금지 — 이미 센 카드 id는 최근 것만 짧게 기억하거나, 날짜별 개수 차이로 증분 계산).
  - `earlyStreak`: 깜빡이를 먼저 켠 차선 변경·회전이 **연속**된 횟수(놓침·늦게 켬이 나오면 0으로).
  - `bestEarlyStreak`: 가장 길었던 연속.
- 사용자가 "아니에요"로 표시한 카드는 모으기에서 뺀다(되돌리면 다시 포함). 피드백이 정확도 데이터라는 원칙 유지.
- 화면: 홈 화면 타일 하나 "모은 잘한 순간 N" + 보조 문구 "깜빡이 먼저 켬 N번 연속(최고 M)". 복기 화면 카드 중 잘한 순간 카드에는 작은 칩 "N번째 잘한 순간"(담백하게).
- 이정표(10·50·100·…번째)는 칩 문구만 살짝 바뀐다("50번째 잘한 순간"). 팝업·소리 없음.

## 바꾸지 않는 것
- 판정 엔진·임계값, 원본 요약 보존 2일, 개수 보존 7일, AI 계약(새 값을 AI로 보내지 않음), 주행 중 잠금, 릴리스 서명.
